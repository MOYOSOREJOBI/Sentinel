     3	## Quant/ML production-mode updates (2026-03-01)
     4	- `scores` persistence is now a real runtime path in `alerts`, and the writer stores `scoring_run_id`, `produced_at`, `artifact_hash`, `model_artifact_hash`, `feature_snapshot_hash`, and `model_version`.
     5	- `/scores` now returns populated lineage fields for each score row, including `model_version`, `produced_at`, and `scoring_run_id`.
     6	- The inference service now loads bundled model artifacts from `services/inference/models/` by default, exposes `fallback_mode`, `model_version`, `model_artifact_hash`, and `trained_at` on `/readyz`, and emits calibration metrics on `/metrics`.
     7	- Model bundle metadata now includes calibration metrics (`auc`, `brier`, `pr_auc`) plus anomaly stability, and `/trust` surfaces that metadata for the UI.
     8	- `integration/ml_scores_persist_test.sh` enforces a clean-boot invariant that `scores.count > 0`, at least one non-fallback model row exists, and lineage columns are non-null before writing `docs/audit/_latest/proofs/S4_ml_real.ok`.

    10	## A. High-level architecture summary
    11	- Current implemented pipeline is effectively:
    12	  - `simulator` produces to `raw.ticks`.
    13	  - `aggregator` consumes `raw.ticks`, writes `raw_ticks` + `candles`, produces `derived.candles`.
    14	  - `features` consumes `derived.candles`, writes `features`, produces `derived.features`.
    15	  - `inference` consumes `derived.features`, produces `derived.scores` only.
    16	  - `alerts` consumes `derived.scores`, writes `scores` + `alerts`, emits SSE + Kafka `alerts.created`.
    17	  - `query` reads from Postgres (`alerts`, `scores`) for frontend.
    18	- Current gating risk: migration `008_scores_lineage.sql` must stay idempotent and compatible with the `scores` hypertable, otherwise the score writer never starts on a clean boot.
    19	
    20	## B. Known working paths
    21	- Health endpoints are present for services and return static `ok` for many services.
    22	- Alert creation path appears to work at least superficially:
    23	  - `alerts` consumes `derived.scores` and inserts `alerts` rows on medium/high/critical severities.
    24	  - SSE endpoint (`/sse/alerts`) broadcasts the consumed score payload to clients.
    25	- Login and `/me` work with JWT cookie-based auth in gateway.
    26	- `audit_log` append-only protection is present at DB trigger level.

    28	## C. Concrete risks grouped by severity
    29	
    30	### Critical
    31	1. **Scores pipeline clean-boot reliability depends on migration correctness.**
    32	   - Root cause: the score writer is implemented in `alerts`, but a broken migration can prevent the writer from starting.
    33	   - Blast radius: `/scores` remains empty after a fresh boot even though the write path exists in code.
    34	   - User impact: UI suggests model output is absent/inconsistent; trust erosion.
    35	   - Ops impact: impossible to investigate historical score generation on cold start.
    36	   - Fix: keep the lineage migration compatible with the `scores` hypertable and retain the idempotent `alerts` writer.
    37	
    38	2. **Privileged and state-changing endpoints lack auth/RBAC enforcement.**
    39	   - Root cause: `alerts` ack and governance routes do not validate JWT/role.
    40	   - Blast radius: any caller can acknowledge alerts, deploy models, start replay.
    41	   - User impact: unauthorized state changes and governance compromise.
    42	   - Ops impact: incident forensics and compliance invalidated.
    43	   - Fix: enforce JWT auth middleware + role checks on alerts/governance service entrypoints.
    44	
    45	3. **Startup race on Kafka topic readiness causing dropped/failed production attempts.**
    46	   - Root cause: simulator starts with compose service health, but topic creation runs later (`run-demo` creates topics after services already running).
    47	   - Blast radius: early ticks fail with `UNKNOWN_TOPIC_OR_PARTITION`; data loss at startup window.
    48	   - User impact: intermittent empty/slow data at startup.
    49	   - Ops impact: nondeterministic boot behavior; flaky demos and deployments.
    50	   - Fix: gate producers on topic existence or auto-create with retries/backoff and readiness probe.
    51	
    52	### Major
    53	1. **False-negative infrastructure health (memcached).**
    54	   - Root cause: memcached healthcheck uses `nc` not installed in image.
    55	   - Blast radius: stack reports unhealthy even if memcached process itself is fine.
    56	   - User impact: noisy/unreliable operational status.
    57	   - Ops impact: alert fatigue; unclear dependency criticality.
    58	   - Fix: use `memcached-tool`/`bash /dev/tcp`/install netcat explicitly; or remove service if unused.
    59	
    60	2. **Metrics contract broken for inference.**
    61	   - Root cause: Prometheus scrapes default `/metrics`; inference exposes only `/healthz` and `/readyz`.
    62	   - Blast radius: inference observability is blind.
    63	   - User impact: failures/perf regressions undetected.
    64	   - Ops impact: cannot track lag, throughput, errors.
    65	   - Fix: add `/metrics` with Prometheus client and instrument Kafka loop.
    66	
    67	3. **Audit trail coverage gaps.**
    68	   - Root cause: `alerts/{id}/ack` and governance actions lack authenticated actor identity and some flows not audited with true principal.
    69	   - Blast radius: audit chain exists but may not cover real privileged actor attribution.
    70	   - Fix: require identity and append audited actor for ack/model/replay actions.
    71	
    72	4. **Query service lacks request-path observability.**
    73	   - Root cause: only startup/shutdown logs; no request/latency/status logs.
    74	   - Blast radius: production debugging and SLO validation are weak.
    75	   - Fix: middleware for structured request logging + DB query error counters/latency histograms.
    76	
    77	### Minor
    78	1. **Timestamp naming inconsistency (`created_at` in DB vs `ts` in API projection).**
    79	   - Not a runtime break in query service (it maps `created_at` -> JSON `ts`), but manual SQL using `alerts.ts` fails, causing operator confusion.
    80	   - Fix: standardize API/DB naming (`created_at` everywhere, or explicit docs/compat alias).
    81	
    82	2. **RBAC package exists but is not integrated.**
    83	   - Indicates intended controls are currently bypassed at runtime.
    84	
    85	3. **Frontend presents empty scores as benign "No scores yet" without degradation signal.**
    86	   - Distinguishes neither startup lag nor broken score writer.

    99	## E. Contract checks between services
   100	- Topic contract appears aligned by name (`raw.ticks`, `derived.candles`, `derived.features`, `derived.scores`), and the persistence contract is now handled by the `alerts` consumer writing the `scores` table.
   101	- Inference emits payload fields `symbol`, `score`, `severity`, `explanation`, `ts` as unix epoch float; no explicit schema versioning.
   102	- Alerts consumes untyped JSON map; no strict validation beyond `symbol` and `severity`, so producer drift can silently break alerting semantics.
   103	- Query `/alerts` emits `ts` sourced from `created_at`, while DB has no `alerts.ts`; operator docs/queries are drift-prone.
   104	- SSE emits raw score payload from Kafka record, not a stable typed alert envelope.
   105	
   106	## F. Database and migration review
   107	- `001_init.sql` creates base schema and append-only audit triggers; currently no `-- +goose Down` section in this file (partial reversibility concern).
   108	- `002_indexes.sql` has Up/Down separation and is reversible.
   109	- Canonical time columns are mixed:
   110	  - `alerts.created_at` (not `ts`)
   111	  - `scores.ts`, `features.ts`, `candles.bucket`
   112	- System still allows some partial-success risk if the stack fails before `alerts` starts, but the runtime path now persists `scores` before creating `alerts`.
   113	- Recommendation: keep persisted `scores` as the prerequisite for alert creation and preserve the current idempotent upsert contract.
   114	
   115	## G. Auth / RBAC / audit review
   116	- Gateway login sets cookie with `HttpOnly` but `Secure=false` (acceptable dev default; not prod-safe).
   117	- JWT expiration set to 24h, no refresh token mechanism.
   118	- `auth.Parse` usage has no explicit issuer/audience validation policy.
   119	- Governance endpoints (`/models/deploy`, `/replay/start`) are now auth + RBAC gated.
   120	- Alerts ack endpoint is now auth + RBAC gated and audited.
   121	- Audit chain integrity mechanism is present and good, but privileged route coverage is incomplete.
   122	
   123	## H. Frontend contract and UX review
   124	- Frontend polls `/alerts` and `/scores` every 5s and connects SSE.
   125	- Empty `/scores` is rendered as normal empty-state text, which masks broken scoring persistence.
   126	- SSE failure/reconnect/error state is not surfaced to user.
   127	- Alert acknowledge call does not enforce authenticated user in UI flow because backend does not require it.
   128	- No explicit degraded-state banner when alerts are flowing but score history is empty.
